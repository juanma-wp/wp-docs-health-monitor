Positives

  • The filter name editor.Autocomplete.completers is correctly documented — it matches the applyFilters call at L46 of packages/block-editor/src/components/autocomplete/index.js and is confirmed by the test suite in packages/editor/src/hooks/test/default-autocompleters.js.
  • The doc correctly states that @wordpress/block-editor's Autocomplete applies the filter while @wordpress/components's foundational Autocomplete does not — this is confirmed by the source: the filter call lives only in packages/block-editor/src/components/autocomplete/index.js, not in packages/components/src/autocomplete/index.tsx.
  • GAP: The filter callback receives completers that may be undefined (not just an empty array) when no completers are registered — the test in default-autocompleters.js explicitly passes undefined as the first argument. The doc's example assumes completers is always an array ([ ...completers, acronymCompleter ]), which would throw if completers is undefined. Developers should guard against this: e.g. return blockName === 'my-plugin/foo' ? [ ...(completers || []), acronymCompleter ] : completers;
