  • Change add_filter( 'render_block_core/paragraph', 'example_add_custom_class_to_paragraph_block', 10, 2 ) to add_filter( 'render_block_core/paragraph', 'example_add_custom_class_to_paragraph_block', 10, 3 )

Positives

  • The block_type_metadata_settings filter documentation correctly documents both parameters ($settings and $metadata) and their types, matching the actual apply_filters( 'block_type_metadata_settings', $settings, $metadata ) call in blocks.php at L754.
  • The blocks.registerBlockType filter documentation accurately describes that it is also applied to each of a block's deprecated settings, which is confirmed in process-block-type.ts where applyFilters('blocks.registerBlockType', ...) is called both for the main block type and within the settings.deprecated.map(...) loop.
  • GAP: The render_block filter documentation does not mention the pre_render_block filter, which fires before render_block and can short-circuit rendering entirely by returning a non-null value. Developers who need to conditionally suppress block rendering entirely would benefit from knowing about this related filter.
