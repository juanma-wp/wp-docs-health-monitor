Update the category property description to include embed in the list of common categories.

  • Change the sentence from "Common categories include text, media, design, widgets, and theme." to "Common categories include text, media, design, widgets, theme, and embed."

Positives

  • The doc correctly identifies all five script/style asset properties (editorScript, editorStyle, script, style, viewScript) and accurately describes their loading contexts (editor-only vs. both editor and front end vs. front-end-only), which matches the schema definitions in schemas/json/block.json and the $script_fields/$style_fields arrays in register_block_type_from_metadata().
  • The doc accurately states that for asset properties you can provide a file path starting with file:, a registered handle, or an array combining both — this matches the remove_block_asset_path_prefix() logic in src/wp-includes/blocks.php which detects the file: prefix and the fallback to treating the value as a plain handle.
  • GAP: The viewStyle property (added in WordPress 6.5) is present in the schema (schemas/json/block.json) and processed in register_block_type_from_metadata() under $style_fields, but the doc's "Files for the block's behavior, output, or style" section does not list viewStyle at all. Developers who need a CSS file loaded only on the front end (not in the editor) would miss this option entirely.
