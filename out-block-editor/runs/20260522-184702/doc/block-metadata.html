Metadata in block.json

✅ No issues found.

Positives

  • The doc correctly documents blockHooks position values (before, after, firstChild, lastChild) — these match exactly the position_mappings array in register_block_type_from_metadata() in blocks.php and the schema's enum for blockHooks pattern properties.
  • The doc accurately describes the render property's exposed PHP variables ($attributes, $content, $block) — these match the render callback closure signature in register_block_type_from_metadata(): static function ( $attributes, $content, $block ) use ( $template_path ).
  • GAP: The WPDefinedAsset object shape documents a handle property that can be set in the .asset.php file to override the auto-generated handle name. This is correctly implemented in register_block_script_handle() via $script_handle = $script_asset['handle'] ?? generate_block_asset_handle(...), but the doc does not mention that providing a handle in the asset file will cause WordPress to skip re-registering if that handle is already registered (wp_script_is( $script_handle, 'registered' )), which is important for shared script handles.
