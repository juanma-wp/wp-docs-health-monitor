Positives

  • The doc correctly identifies all four public API functions (register_block_pattern, unregister_block_pattern, register_block_pattern_category, unregister_block_pattern_category) and their signatures match the source exactly.
  • The doc correctly states that register_block_pattern() should be called from a handler attached to the init hook, which is consistent with how _register_theme_block_patterns is hooked via add_action( 'init', '_register_theme_block_patterns' ) in the source.
  • GAP: register_block_pattern_category accepts a description property (used by all core categories in _register_core_block_patterns_and_categories()), but the doc only documents label as a property, leaving developers unaware they can provide a description for their custom categories.
