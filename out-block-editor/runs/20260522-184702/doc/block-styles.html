💡

Update the register_block_style documentation to clarify that inline_style, style_handle, and style_data are all optional.

  • Change "should also include an inline_style or a style_handle or a style_data property" to something like "may optionally include an inline_style, style_handle, or style_data property to associate CSS with the style".
  • Add a note that omitting all three is valid — the style will still register and apply its CSS class, but the developer is responsible for providing the CSS through another means (e.g. an existing stylesheet or inline tag).
  • This matches the explicit note in WP_Block_Styles_Registry::register(): "you could also skip them and provide CSS styles in any stylesheet or with an inline tag."

Positives

  • The doc correctly documents that registerBlockStyle (JS) accepts a string or array of block names as its first argument, matching the blockNames: string | string[] signature in registration.ts.
  • The doc accurately describes the server-side register_block_style PHP function signature — two positional arguments ($block_name and $style_properties) with name and label as mandatory keys — which matches src/wp-includes/blocks.php.
  • GAP: The JS registerBlockStyle function also accepts an array of BlockStyle objects as its second argument (styleVariation: BlockStyle | BlockStyle[]), but the documentation only shows a single style object in all examples. Developers who want to register multiple styles in one call cannot discover this from the docs.
