schema = typeof schema === 'function' ? schema( schemaArgs ) : schema;
💡

Fix the arrow-function schema example so it returns an object literal instead of a labeled statement block.

  • Wrap the object in parentheses for an implicit return: schema = ({ phrasingContentSchema }) => ({ div: { ... } })
  • Without the parentheses, { div: { ... } } is parsed as a JavaScript function body containing a labeled statement named div, so the function returns undefined.
  • The runtime in utils.ts calls schema( schemaArgs ) and uses the return value directly; when the function returns undefined, the schema is silently empty and the raw transform will never match any HTML.

Positives

  • The rawHandler signature documented as rawHandler({ HTML }) returning blocks is accurate — the source confirms export function rawHandler( { HTML = '' }: { HTML?: string } ): Block[].
  • The isMultiBlock transform behaviour is correctly documented: the source in switchToBlockType confirms that when transformation.isMultiBlock is true, transform is called with arrays of attributes and inner blocks respectively.
  • GAP: The schema parameter for raw transforms also accepts a function that receives an isPaste boolean as a second argument (alongside phrasingContentSchema), but the documentation only mentions phrasingContentSchema. Developers who need to distinguish paste vs. drag-drop/convert operations cannot discover this from the docs.
