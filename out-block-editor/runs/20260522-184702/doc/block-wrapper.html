💡

Update the useBlockProps() documentation to clarify that wp-block is conditionally applied.

  • In the bullet point listing default classes, change "The wp-block class for general block styling" to "The wp-block class for general block styling (only added when the block has no alignment set; omitted when isAligned is true)."
  • Add a note that aligned blocks intentionally omit wp-block so that editor styles do not interfere with alignment-specific layout.

Positives

  • The doc correctly states that useBlockProps.save() is the client-side equivalent of get_block_wrapper_attributes() for dynamic blocks — both are confirmed to exist and serve that role in the source code.
  • The doc accurately describes that useBlockProps() automatically adds id, role, aria-label, data-block, data-type, and data-title attributes — all of these are confirmed present in the return statement of useBlockProps in index.js.
  • GAP: useBlockProps() emits a warning() when used with a block registered at API version < 2 (blockApiVersion < 2), but the doc never mentions this requirement beyond a passing note in the JSDoc. Developers who use useBlockProps() without setting apiVersion: 2 or higher in their block.json will see a console warning and potentially broken behaviour.
