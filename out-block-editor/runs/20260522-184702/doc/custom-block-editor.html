Positives

  • The doc correctly describes <BlockEditorProvider> accepting value, onInput, onChange, and settings props — this matches the JSX shown in the companion plugin and the component's documented contract.
  • The registerCoreBlocks() usage in the bootstrap snippet is accurate: the exported function in packages/block-library/src/index.js is indeed named registerCoreBlocks and accepts an optional blocks array, matching the doc's call with no arguments.
  • GAP: BlockListItems is exported from packages/block-editor/src/components/block-list/index.js and provides a synchronous (non-async-mode) way to render a list of blocks, but the doc never mentions it. Developers building custom editors who need synchronous block rendering would benefit from knowing this alternative to <BlockList>.
