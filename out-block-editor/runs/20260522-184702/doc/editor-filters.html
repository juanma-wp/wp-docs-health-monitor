💡

Update the editor.PostFeaturedImage.imageSize filter documentation to correct both the default size and the fallback behaviour.

  • The actual default size passed to the filter is 'large' (not 'post-thumbnail'): change "It defaults to 'post-thumbnail'" to "It defaults to 'large'".
  • The fallback when the default size is unavailable is 'thumbnail' (not 'full'): change "will fail back to the full image size" to "will fall back to the 'thumbnail' image size".
  • Note that if neither 'large' nor 'thumbnail' sizes exist in the media object, the code ultimately falls back to the full/original image (media.source_url), but this is a last-resort path, not the documented fallback.

Positives

  • The block_editor_settings_all filter documentation correctly identifies both parameters ($settings array and $context as a WP_Block_Editor_Context instance), matching the actual filter signature at line 645 of src/wp-includes/block-editor.php.
  • The should_load_remote_block_patterns filter documentation is accurate — the filter fires with a default of true and is used in three separate places in src/wp-includes/block-patterns.php (lines 299, 332, 371), all consistent with the documented usage of __return_false.
  • GAP: The editor.PostFeaturedImage.imageSize filter is called twice in post-featured-image/index.js — once for the default size and once for the fallback size — but the doc only mentions the default-size invocation. Developers implementing this filter should know it may be called a second time with 'thumbnail' as the initial value when the first call's result is not found in the media object.
