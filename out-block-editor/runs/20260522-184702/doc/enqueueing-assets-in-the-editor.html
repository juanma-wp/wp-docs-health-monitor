Enqueueing assets in the Editor

100 healthy

✅ No issues found.

Positives

  • The doc correctly identifies enqueue_block_editor_assets as the hook for Editor UI assets — confirmed firing in src/wp-admin/edit-form-blocks.php (L345), src/wp-admin/site-editor.php (L314), and src/wp-admin/widgets-form-blocks.php (L83).
  • The doc correctly states that enqueue_block_assets fires both in the Editor and on the front end — confirmed by do_action( 'enqueue_block_assets' ) appearing in both src/wp-includes/script-loader.php (L2516, inside wp_common_block_scripts_and_styles()) and src/wp-includes/block-editor.php (L342, inside _wp_get_iframed_editor_assets()).
  • GAP: The doc does not mention the block_editor_settings_all filter's second parameter type. The filter passes a WP_Block_Editor_Context object as the second argument (confirmed in src/wp-includes/block-editor.php), but the doc's example callback declares it as $editor_context typed as string in the PHPDoc comment (@param string $editor_context). Developers who inspect the actual value will find an object, not a string.
