Positives

  • The doc correctly identifies wp_register_block_types_from_metadata_collection() as the recommended approach for WordPress 6.8+ (matching the @since 6.8.0 tag in src/wp-includes/blocks.php) and accurately describes it as registering all blocks from a generated blocks-manifest.php file in a single call.
  • The doc accurately describes registerBlockType as the client-side function for registering a block, correctly noting it is called in index.js and receives the edit and save functions — consistent with the function signature in packages/blocks/src/api/registration.ts.
  • GAP: The block.json schema supports a viewScriptModule field (for ES module scripts loaded only on the front end), but the doc's list of important block.json properties omits it entirely. Developers building interactive blocks with the Interactivity API would benefit from knowing this field exists alongside viewScript.
