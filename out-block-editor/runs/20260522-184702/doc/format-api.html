💡

Correct the description of RichTextToolbarButton placement in the relevant step.

  • RichTextToolbarButton fills the RichText.ToolbarControls slot. When a name prop is provided (e.g. name="bold", name="italic", name="link"), it fills a named sub-slot and renders directly in the inline format toolbar alongside Bold/Italic/Link. When no name is provided, it fills the generic RichText.ToolbarControls slot, which is rendered inside a "More" DropdownMenu (see format-toolbar/index.js).
  • The doc's contrast — "RichTextToolbarButton = dropdown, BlockControls = toolbar" — is only partially correct: named sub-slots render directly in the toolbar, not in the dropdown. Update the prose to clarify that unnamed RichTextToolbarButton usage lands in the "More" dropdown, while passing a recognised name value places the button directly in the inline format toolbar. BlockControls places the button in the block-level (top) toolbar, which is a separate concept.

Positives

  • The registerFormatType call signature and required properties (title, tagName, className, edit) match the source exactly — the code validates all four fields and errors if they are missing or malformed.
  • The toggleFormat(value, format) two-argument signature shown in all code examples is correct and matches the exported function signature in packages/rich-text/src/toggle-format.js.
  • GAP: registerFormatType silently validates that keywords, if provided, must have at most 3 entries (enforced in the source with a console.error). The doc never mentions the keywords property at all, which could surprise developers who want to make their format discoverable via search.
