Positives

  • The documentation accurately lists all eight fundamental topic areas that correspond to real block development concepts (file structure, block.json, registration, block wrapper, editor integration, markup representation, static/dynamic rendering, and JavaScript), providing a correct high-level navigation index.
  • The schema confirms that attributes and supports are valid top-level properties in block.json, consistent with the doc's mention of them as 'relevant properties' of the block.json file.
  • GAP: The schema's required array lists apiVersion, name, and title as required fields for block.json, but this index page (and potentially the linked block.json fundamentals page) does not surface this requirement. Developers scaffolding a block without knowing these three fields are required could produce invalid block definitions.
