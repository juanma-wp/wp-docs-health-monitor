Positives

  • The four filter callback signatures documented (i18n.gettext, i18n.gettext_with_context, i18n.ngettext, i18n.ngettext_with_context) exactly match the hooks.applyFilters(...) call sites in create-i18n.ts — argument order and count are correct in all four cases.
  • The doc's explanation of text-domain-specific filter naming (appending _ + domain) is confirmed by the code: hooks.applyFilters('i18n.gettext_' + getFilterDomain(domain), ...) and getFilterDomain returns domain || 'default', which directly validates both the _woocommerce and _default suffix examples.
  • GAP: The doc never mentions the i18n.has_translation / i18n.has_translation_<domain> filters fired inside hasTranslation() (lines ~350–360 of create-i18n.ts). Developers who want to override hasTranslation() results would benefit from knowing these filterable hooks exist.
