Positives

  • The doc correctly identifies wp_interactivity_state() as the server-side function for setting store state, and the code confirms this function exists with the exact signature shown in the example (wp_interactivity_state( 'favoriteMovies', array(...) )).
  • The doc correctly states the Interactivity API does not use eval() or the Function() constructor — the source code for interactivity-api.php contains no such calls, consistent with the security claim.
  • GAP: The doc never mentions wp_interactivity_get_element() (added in 6.7.0), which returns the current element being processed during directive handling. Block developers writing custom directive processors would benefit from knowing this function exists and its return shape array{attributes: array<string, string|bool>}|null.
