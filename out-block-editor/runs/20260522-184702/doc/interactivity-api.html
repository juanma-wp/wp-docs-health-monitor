Positives

  • The doc correctly states that viewScriptModule accepts a file path string (e.g. "file:./view.js"), which matches the block.json schema's definition of viewScriptModule as a string or string[].
  • The doc accurately describes the supports.interactivity field as accepting true (boolean), which aligns with the schema's oneOf allowing a boolean type for that property.
  • GAP: The schema shows supports.interactivity can also be an object with clientNavigation and interactive sub-properties, but the doc only documents the boolean form ("interactivity": true). Developers who need fine-grained control (e.g., marking a block as compatible with client-side navigation without being fully interactive) would benefit from knowing about the object form.
