Positives

  • The doc's Image block markup example (<!-- wp:image {"sizeSlug":"large"} -->) accurately reflects the sizeSlug attribute used in save.js, which reads sizeSlug from attributes and applies it as size-${sizeSlug} class — consistent with the size-large class shown in the example.
  • The doc correctly states that for dynamically rendered blocks (save = null) only a placeholder comment with block attributes is saved, with no HTML markup besides the comment. This is an accurate description of WordPress's block serialization behaviour for dynamic blocks.
  • GAP: The Image block's save function supports several attributes not mentioned anywhere in the doc's markup example — including href/linkTarget/rel (linked images), caption, width/height, and border/shadow styles. Developers authoring or migrating Image block markup by hand would benefit from knowing these attributes are serialized into the block comment and affect the saved output.
