Positives

  • The example correctly imports PluginBlockSettingsMenuItem from @wordpress/editor, which matches the canonical export confirmed in packages/edit-post/src/deprecated.js (EditorPluginBlockSettingsMenuItem re-exported from @wordpress/editor).
  • GAP: The PluginBlockSettingsMenuItem component accepts props that are passed through directly to the underlying EditorPluginBlockSettingsMenuItem, but the documentation does not list or describe any of the accepted props (e.g., allowedBlocks, icon, label, onClick). Developers relying solely on the doc would have no reference for what props are valid beyond what they can infer from the example.
  • GAP: The registerPlugin API (used in the example) silently ignores duplicate plugin registrations — it logs a console.error but does NOT return null and continues to overwrite. Developers expecting a hard failure on duplicate registration would be surprised by this behaviour, and the registerPlugin docs do not mention it.
