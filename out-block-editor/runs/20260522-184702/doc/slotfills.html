SlotFills are created using createSlotFill. This creates two components, Slot and Fill which are then used to create a new component that is exported on the wp.plugins global.

gutenberg:packages/components/src/slot-fill/index.tsx

return {
		name: key,
		Fill: FillComponent,
		Slot: SlotComponent,
	};
💡

Update the prose description of createSlotFill to reflect that it returns an object with three properties, not just two components.

  • Change "This creates two components, Slot and Fill" to "This returns an object with three properties: name, Fill, and Slot"
  • Note that name holds the slot key and is the preferred replacement for the deprecated Slot.__unstableName (deprecated in 6.8.0)

Positives

  • The doc's code examples correctly import SlotFills from @wordpress/editor (e.g. import { PluginDocumentSettingPanel, store as editorStore } from '@wordpress/editor'), which matches the actual package structure.
  • The registerPlugin usage in examples correctly passes { render: ComponentName } matching the PluginSettings type in packages/plugins/src/api/index.ts which requires render: ComponentType.
  • GAP: createSlotFill now returns a name property (the slot key) in addition to Fill and Slot. The doc's definition snippet omits this third return value, and developers should know about it as a replacement for the deprecated Slot.__unstableName property (marked @deprecated 6.8.0 in source).
