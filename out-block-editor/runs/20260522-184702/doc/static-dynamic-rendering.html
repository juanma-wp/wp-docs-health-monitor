Static or Dynamic rendering of a block

✅ No issues found.

Positives

  • The doc correctly describes the three parameters passed to dynamic rendering callbacks ($attributes, $content, $block / WP_Block instance), which matches the render_callback closure registered in register_block_type_from_metadata() in blocks.php: static function ( $attributes, $content, $block ) use ( $template_path ).
  • The doc accurately states that when save returns null the Block Editor skips block markup validation — this is consistent with the WordPress block validation architecture where a null save function means no stored HTML to validate against.
  • GAP: The doc does not mention that the render field in block.json (which maps to a render.php file) was added in WordPress 6.1.0 (per the @since 6.1.0 tag in register_block_type_from_metadata). Noting the minimum WordPress version required for this approach would help developers targeting older installs.
