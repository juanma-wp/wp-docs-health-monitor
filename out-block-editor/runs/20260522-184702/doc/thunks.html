export function toggleFeature( scope, featureName ) {
	return function ( { registry } ) {
		deprecated( `dispatch( 'core/interface' ).toggleFeature`, {
			since: '6.0',
			alternative: `dispatch( 'core/preferences' ).toggle`,
		} );

		registry.dispatch( preferencesStore ).toggle( scope, featureName );
	};
}

💡

Update the toggleFeature code example to reflect the actual current implementation.

  • Replace the documented thunk body { select, dispatch } with { registry } — the function no longer destructures select or dispatch.
  • Remove the calls to select.isFeatureActive and dispatch.setFeatureValue; neither exists on the current interface store's public API (setFeatureValue is itself deprecated since 6.0).
  • Add the deprecated() call and the delegation to registry.dispatch( preferencesStore ).toggle( scope, featureName ) to match the real implementation.
  • Consider adding a note that toggleFeature has been deprecated since 6.0 and that callers should use dispatch( 'core/preferences' ).toggle directly.

Positives

  • The doc's description of registry.select( storeName ) returning an object of selectors is accurate and matches the pattern used throughout packages/interface/src/store/actions.js, e.g. registry.select( preferencesStore ).get( scope, ... ).
  • The doc correctly states that resolveSelect 'returns a promise that resolves with the value provided by the related resolver', which matches the exported symbol description: 'modified so that they return promises that resolve to their eventual values, after any resolvers have ran'.
  • GAP: The doc never mentions that dispatch inside a thunk also accepts a plain Redux action object (e.g. dispatch({ type: 'SET_TEMPERATURE', ... })), but this is shown in the enableComplementaryArea thunk in packages/interface/src/store/actions.js (dispatch({ type: 'ENABLE_COMPLEMENTARY_AREA', scope, area })), confirming the inline-action dispatch pattern is real and useful for developers to know.
