Positives

  • The doc correctly describes getServerState() and getServerContext() as returning deep clones that do not affect the actual server state/context when mutated — this matches deepClone(serverStates.get(ns)) in store.ts and deepClone(scope.serverContext[...]) in scopes.ts.
  • The doc accurately describes withSyncEvent() as required for actions that need synchronous access to the event object (e.g., event.preventDefault()), which matches the SyncAwareFunction interface and withSyncEvent implementation in utils.ts that sets sync = true on the callback.
  • GAP: getConfig() in store.ts accepts an optional namespace parameter (getConfig(namespace?: string)), allowing callers to retrieve config for a namespace other than the current one. The doc's Config section only shows getConfig() called with no arguments and never mentions the optional namespace parameter, which could be useful for cross-namespace config access.
