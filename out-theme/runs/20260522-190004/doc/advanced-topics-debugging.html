Positives

  • The doc correctly describes WP_DEBUG_DISPLAY's default behaviour: when WP_DEBUG is enabled, messages are shown on screen, so WP_DEBUG_DISPLAY does not need to be explicitly defined to get on-screen output — this matches the well-known WordPress core behaviour.
  • GAP: The doc mentions WP_DEBUG_LOG can be set to true to log to /wp-content/debug.log, but does not mention that WP_DEBUG_LOG also accepts a string file path (e.g., define( 'WP_DEBUG_LOG', '/path/to/custom.log' )) to redirect logs to a custom location — a useful capability for developers who cannot write to wp-content.
  • The three recommended plugins (Debug Bar, Query Monitor, Log Deprecated Notices) are all real, actively maintained plugins in the WordPress Plugin Directory, and their described capabilities are accurate.
