Positives

  • The doc correctly describes the template hierarchy fallback behaviour — if no specific template is found, WordPress falls back to index.html — which aligns with the well-established WordPress template hierarchy.
  • The doc accurately distinguishes between the /templates folder for template files and the /parts folder for template parts, which matches the block theme directory conventions.
  • GAP: The doc lists category.html and tag.html in the descriptive table of common templates but omits them from the visual directory tree example above it (templates/ listing). Developers scanning only the tree might not realise these are valid template files they can create.
