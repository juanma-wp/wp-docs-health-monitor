Positives

  • The doc correctly identifies path as the key argument needed to trigger CSS inlining in <head>, which matches the wp_style_add_data( $handle, 'path', ... ) mechanism in wp_maybe_inline_styles() and the wp_enqueue_block_style() implementation.
  • The doc correctly states that wp_enqueue_block_style() should be called on the init hook, and the code confirms the function checks did_action( 'wp_enqueue_scripts' ) to decide between wp_footer and wp_enqueue_scripts hooks, making init the safe registration point.
  • GAP: wp_enqueue_block_style() automatically handles RTL stylesheets — if a file named {handle}-rtl.css exists alongside the path-provided stylesheet, it is registered and activated for RTL sites. The documentation does not mention this automatic RTL support, which would be valuable for theme developers targeting international audiences.
