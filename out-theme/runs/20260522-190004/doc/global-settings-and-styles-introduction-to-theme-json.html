Positives

  • The documented top-level properties (version, $schema, settings, styles, customTemplates, templateParts, patterns) match the structure shown in the schema file (schemas/json/theme.json), which validates the same property names via settingsProperties and the root object definition.
  • The doc's code example { "$schema": "https://schemas.wp.org/trunk/theme.json", "version": 2 } is consistent with the schema's own $schema reference URL and the integer type expected for version.
  • GAP: The schema defines a version 3 path is not mentioned — but more importantly, the schema exposes many sub-properties under settings (e.g., appearanceTools, background, border, color, dimensions, layout, lightbox, position, shadow, spacing, typography, custom) that the introduction page intentionally defers to sub-pages. This is appropriate for an introduction page and is not a gap at this level of documentation.
