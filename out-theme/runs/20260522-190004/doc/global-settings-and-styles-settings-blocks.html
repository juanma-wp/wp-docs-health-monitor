Positives

  • The documented default block settings for core/button (border.radius: true) and core/pullquote (border.color, border.radius, border.style, border.width all true) are accurately reflected in the schema, which confirms these are real, schema-defined properties.
  • The doc correctly describes the settings.blocks namespace/slug pattern (e.g. core/cover), which matches the schema's patternProperties regex ^[a-z][a-z0-9-]*/[a-z][a-z0-9-]*$ and the explicit core/cover entry in settingsBlocksPropertiesComplete.
  • GAP: The schema supports settings.blocks entries for many blocks beyond Button and Pullquote (e.g. core/navigation-link supports custom states via @current), but the doc only mentions Button and Pullquote as having default block-level settings. Developers may not realise other blocks have special schema-level capabilities.
