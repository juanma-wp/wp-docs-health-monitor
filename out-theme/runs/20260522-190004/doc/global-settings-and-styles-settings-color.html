💡

Fix the property path reference in the 'User-customized colors' section.

  • Change settings.colors.custom (plural 'colors') to settings.color.custom (singular 'color') to match the actual theme.json property name as defined in the schema.

Positives

  • The documentation correctly identifies background, custom, customDuotone, customGradient, defaultDuotone, defaultGradients, defaultPalette, and text as all defaulting to true, which matches the schema's "default": true entries for each of those properties.
  • The three required properties for a duotone preset object (colors, name, slug) are correctly documented and match the schema's "required": [ "name", "slug", "colors" ] definition.
  • GAP: The schema defines settings.color.heading, settings.color.button, and settings.color.caption as additional boolean color controls (all defaulting to true), but the documentation never mentions these properties. Theme authors who want to disable heading, button, or caption color controls in the editor would have no way to discover this from the doc.
