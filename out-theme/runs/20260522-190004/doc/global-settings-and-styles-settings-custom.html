The generated CSS custom property will follow this pattern: --wp--custom--{key}--{value}.

gutenberg:schemas/json/theme.json

Generate custom CSS custom properties of the form `--wp--custom--{key}--{nested-key}: {value};`.
💡

Correct the CSS custom property pattern description in the 'Overview of the custom setting' section.

  • Replace --wp--custom--{key}--{value} with --wp--custom--{key}--{nested-key}: {value}; to accurately show that nested keys become additional ---separated segments in the property name, and the value is assigned after the colon.
  • Clarify that {value} is the CSS value assigned to the property (after the colon), not a suffix appended to the property name itself.

Positives

  • The doc correctly explains that camelCase keys are automatically hyphenated (e.g., lineHeight → line-height), which matches the schema description: 'camelCased keys are transformed to kebab-case as to follow the CSS property naming schema.'
  • The doc accurately describes that nested objects produce longer property names with -- separators between depth levels, consistent with the schema: 'Keys at different depth levels are separated by --'.
  • GAP: The schema notes that 'keys should not include -- in the name' because double-hyphens are used as depth separators — this constraint is never mentioned in the documentation, and a developer who uses -- in a key name would get malformed CSS custom property names.
