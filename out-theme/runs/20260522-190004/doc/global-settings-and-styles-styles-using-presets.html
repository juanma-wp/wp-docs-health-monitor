--wp--preset--font-size--{slug}
💡

Fix the CSS custom property name for font-size presets in the 'What are presets?' section.

  • Change --wp--preset--font-size–{$slug} to --wp--preset--font-size--{slug}: the separator before {slug} is an en-dash (–, U+2013) in the doc but must be a double hyphen (--), and the $ prefix on slug is incorrect (it is not a PHP variable here).

Positives

  • The var:preset|color|base syntax and its mapping to CSS custom properties like --wp--preset--color--base is correctly documented and consistent with the schema's description of how palette presets generate custom properties.
  • The var:custom syntax for referencing custom settings (e.g., var:custom|line-height|md) correctly mirrors the camelCase-to-kebab-case transformation described in the schema's settingsCustomAdditionalProperties definition (camelCased keys are transformed to kebab-case).
  • GAP: The schema defines settings.border.radiusSizes as a preset category (generating --wp--preset--border-radius--{slug}), but the doc's 'Available presets' list omits Border entirely. Developers wanting to register border-radius presets would not find this feature documented here.
