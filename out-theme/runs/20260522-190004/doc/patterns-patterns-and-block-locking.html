Positives

  • The doc correctly documents all three valid templateLock values (all, insert, contentOnly) which align with the block locking API's supported enum values as reflected in the schema and block editor internals.
  • The doc accurately describes the lock attribute shape with move and remove boolean keys, and the examples shown (e.g., {"lock":{"move":true,"remove":false}}) are consistent with how the block locking API serializes these values in block markup.
  • GAP: The supports.lock property in block.json (schema) allows a block type to disable the lock UI entirely by setting lock: false in its supports declaration — this is a block-registration-level control distinct from the per-instance lock attribute described in the doc, and is never mentioned. Developers building custom blocks who want to prevent the lock UI from appearing at all would benefit from knowing this.
