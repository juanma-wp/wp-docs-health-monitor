Positives

  • The doc correctly describes the distinction between getEntityRecord (returns server-persisted data, ignores local edits) and getEditedEntityRecord (merges local edits on top), which matches the selector implementations in packages/core-data/src/selectors.ts exactly.
  • The doc accurately states that saveEditedEntityRecord returns a promise that resolves with the updated record on success and an empty/falsy value on failure — matching the saveEditedEntityRecord action in packages/core-data/src/actions.js, which delegates to saveEntityRecord and returns updatedRecord (undefined on error).
  • GAP: getEditedEntityRecord can return false (not just an object) when both the raw record and edits are absent — the selector explicitly returns false in that case (if ( ! raw && ! edited ) { return false; }). The doc never mentions this, so code like page.title in the form would throw if the record hasn't loaded yet. Developers should guard with if ( ! page ) return null; before rendering.
