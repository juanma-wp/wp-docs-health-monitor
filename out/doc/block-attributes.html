💡

Add rich-text to the list of valid type values in the block attributes documentation.

  • In the bullet list under "The type field MUST be one of the following:", add - \rich-text\` as a valid type value (it appears between string and integer` in the schema enum).
  • Note that rich-text is only valid when type is a single string value, not when it is an array of types — the schema's array variant (oneOf second branch) does not include rich-text, so this distinction should be documented.

Positives

  • The documentation correctly describes the role property with both content and local values, which matches the schema's "enum": [ "content", "local" ] in schemas/json/block.json.
  • The documentation accurately describes the query source, including that entries are determined by the selector argument and that the query field is a nested block attributes definition — this matches the schema's "type": "object" for the query property and the runtime behaviour in matchers.ts.
  • GAP: The source value rich-text is implemented in packages/blocks/src/api/matchers.ts as a full exported function returning RichTextData, but the documentation omits it entirely from the Value source section. Developers using RichText components would benefit from knowing this source type exists and what it returns.
