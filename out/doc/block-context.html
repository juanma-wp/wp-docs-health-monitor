Positives

  • The doc correctly describes providesContext as 'an object which maps a context name to one of the block's own attributes' — this matches the block.json schema definition: "Context provided for available access by descendants of blocks of this type, in the form of an object which maps a context name to one of the block's own attribute."
  • The doc correctly states that usesContext should be assigned as 'an array of the context names the block seeks to inherit' — this matches the schema: "type": "array", "items": { "type": "string" } for the usesContext property.
  • GAP: The doc does not mention that block context is also available via block.json metadata (the providesContext and usesContext fields in block.json), which is the modern recommended approach for registering blocks. Developers using block.json-based registration would benefit from knowing these fields are supported natively in the schema.
