💡

Add embed to the list of common categories in the category description.

  • The schema (schemas/json/block.json) enumerates six core categories: text, media, design, widgets, theme, and embed. The WordPress core function get_default_block_categories() in src/wp-includes/block-editor.php also registers embed as a built-in category.
  • Change the sentence to: "Common categories include text, media, design, widgets, theme, and embed."

Positives

  • The doc correctly describes viewScript as a JavaScript file intended solely for the front end — this matches the schema's viewScript description ('It will be enqueued only when viewing the content on the front of the site') and the runtime code in register_block_script_handle() which applies a defer strategy specifically for the viewScript field.
  • The doc's block supports color example (text, link, background) accurately reflects the schema's supports.color sub-properties, all of which exist with the correct names in schemas/json/block.json.
  • GAP: The viewStyle property (enqueues a CSS file only on the front end, added in WordPress 6.5) is present in the schema and handled in register_block_type_from_metadata() under $style_fields, but is not mentioned anywhere in the doc's 'Files for the block's behavior, output, or style' section. Developers who need front-end-only styles without editor overhead would benefit from knowing this property exists.
