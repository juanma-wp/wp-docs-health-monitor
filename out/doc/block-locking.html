Positives

  • The doc correctly identifies both parameters passed to the block_editor_settings_all filter callback ($settings and $context), which matches the hook's documented contract in WordPress core.
  • The doc accurately describes templateLock: 'contentOnly' as the mechanism for content-only editing, consistent with the block template locking API introduced in WordPress 6.1.
  • GAP: The doc does not mention that templateLock can also accept 'all' or 'insert' as values (in addition to 'contentOnly'), which are valid options for restricting block insertion and all editing within a template — developers would benefit from knowing the full set of accepted values.
