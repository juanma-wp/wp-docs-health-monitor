Metadata in block.json

100 healthy

✅ No issues found.

Positives

  • The blockHooks position values documented as before, after, firstChild, lastChild correctly match the schema enum ["before", "after", "firstChild", "lastChild"] in schemas/json/block.json, and the PHP $position_mappings array in blocks.php correctly maps these camelCase values to their snake_case internal equivalents.
  • The render property documentation accurately describes the three variables exposed to the render.php file ($attributes, $content, $block) — confirmed by the render_callback closure in register_block_type_from_metadata() which passes exactly $attributes, $content, and $block (a WP_Block instance) to the required template file.
  • GAP: The WPDefinedAsset object shape documents a handle property that can be set in the .asset.php file to override the auto-generated script handle. This is confirmed in register_block_script_handle() via $script_handle = isset( $script_asset['handle'] ) ? $script_asset['handle'] : generate_block_asset_handle(...), but the doc's .asset.php example does not show the optional handle key — developers who want a stable, predictable handle name would benefit from knowing this option exists.
