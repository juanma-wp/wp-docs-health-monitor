gutenberg:schemas/json/block.json

"required": [ "name", "title" ]
💡

Update the title field description in the block variations documentation to reflect that it is required when defining variations in block.json.

  • Change "title (optional, type string)" to "title (required, type string)" in the variations property table.
  • Add a note clarifying that title is required in block.json variation items (per the schema's required: ["name", "title"] constraint on variation array items at line ~1085 of schemas/json/block.json), even though it may be omitted when registering variations via the JavaScript registerBlockVariation() API.

Positives

  • The doc correctly documents the get_block_type_variations PHP filter hook name, which matches the firing site in src/wp-includes/class-wp-block-type.php at L616: apply_filters( 'get_block_type_variations', $this->variations, $this ).
  • The doc accurately describes unregisterBlockVariation() accepting a block name and variation name string — matching the exported signature unregisterBlockVariation: (blockName: string, variationName: string | string[]) => void. GAP: the doc omits that variationName can also be a string[] (array of names), allowing batch unregistration in a single call.
  • GAP: registerBlockVariation() also accepts an array of variation objects (BlockVariation | BlockVariation[]) as its second argument, but the doc only shows the single-variation form. Developers could register multiple variations in one call.
