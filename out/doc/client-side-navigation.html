Client-Side Navigation

✅ No issues found.

Positives

  • The doc correctly describes getServerState() as returning a deep clone of server-provided state that updates on navigation without overwriting client state — this matches the implementation in packages/interactivity/src/store.ts, which calls deepClone(serverStates.get(ns)) and resets serverStates in populateServerData().
  • The doc accurately describes getServerContext() as reactive and returning a deep clone of server-provided context, consistent with packages/interactivity/src/scopes.ts which calls deepClone(scope.serverContext[...]) and accesses navigationContextSignal.value to create the reactive subscription.
  • GAP: The universalUnlock string documented in the source ('I acknowledge that using a private store means my plugin will inevitably break on the next store release.') differs from the privateApis consent string ('I acknowledge that using private APIs means my theme or plugin will inevitably break in the next version of WordPress.'). The doc never mentions either string, but developers using store() with a lock string need the exact value — the doc could benefit from noting the correct lock string for private stores.
