It defaults to 'post-thumbnail' and will fail back to the full image size when the specified image size doesn't exist in the media object.

gutenberg:packages/editor/src/components/post-featured-image/index.js

const defaultSize = applyFilters(
		'editor.PostFeaturedImage.imageSize',
		'large',
		media.id,
		postId
	);
💡

Update the editor.PostFeaturedImage.imageSize filter documentation to correct both the default size and the fallback chain.

  • Change "It defaults to 'post-thumbnail'" to "It defaults to 'large'" — the filter is invoked with 'large' as the second argument (the default size).
  • Change "will fail back to the full image size" to "will fall back to 'thumbnail' (the filter is invoked a second time with 'thumbnail' as the default), and if that is also unavailable, will use the full image dimensions via media.source_url".

Positives

  • The editor.ErrorBoundary.errorLogged action hook is correctly documented — the code in packages/editor/src/components/error-boundary/index.js, packages/customize-widgets/src/components/error-boundary/index.js, and packages/edit-widgets/src/components/error-boundary/index.js all fire doAction('editor.ErrorBoundary.errorLogged', error) exactly as described, passing the error object as the sole argument.
  • The should_load_remote_block_patterns filter is correctly documented as defaulting to true and accepting __return_false to disable remote patterns — confirmed by apply_filters('should_load_remote_block_patterns', true) in src/wp-includes/block-patterns.php at multiple call sites.
  • GAP: The media.crossOrigin filter accepts a second mediaSrc argument (the URL of the foreign media), which the doc mentions in a comment inside the example snippet but does not formally document as part of the filter's parameter list. Developers implementing this filter would benefit from a formal @param description noting that the second argument is the media source URL string.
