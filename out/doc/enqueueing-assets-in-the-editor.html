Positives

  • The doc correctly identifies enqueue_block_editor_assets as the hook for Editor UI assets — confirmed firing in src/wp-admin/edit-form-blocks.php (L339), src/wp-admin/site-editor.php (L308), and src/wp-admin/widgets-form-blocks.php (L83).
  • The doc correctly states that enqueue_block_assets fires both in the Editor and on the front end — confirmed by do_action( 'enqueue_block_assets' ) in both src/wp-includes/script-loader.php (L2497, inside wp_common_block_scripts_and_styles()) and src/wp-includes/block-editor.php (L341, inside _wp_get_iframed_editor_assets()).
  • GAP: wp_enqueue_block_style() (in src/wp-includes/script-loader.php) accepts a $path argument for potential CSS inlining via wp_maybe_inline_styles(), but the doc's Theme section only mentions the function without noting this performance-relevant capability.
