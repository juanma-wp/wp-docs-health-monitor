Positives

  • The doc correctly identifies wp_register_block_types_from_metadata_collection() as the recommended registration approach for WordPress 6.8+ with wp-scripts, which matches the @since 6.8.0 tag and function signature in src/wp-includes/blocks.php.
  • The doc accurately describes the block.json schema properties (editorScript, style, editorStyle, render, viewScript) and their typical build output filenames, all of which are confirmed present in the schemas/json/block.json schema.
  • GAP: The block.json schema also supports viewScriptModule (for ES module scripts) and viewStyle (frontend-only styles), neither of which is mentioned in the file structure doc's list of important block.json properties. Developers building interactive blocks with the Interactivity API would benefit from knowing about viewScriptModule.
