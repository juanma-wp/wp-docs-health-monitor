Positives

  • The doc's description of registerPlugin as the API for defining plugin UI elements is accurate — the function exists in packages/plugins/src/api/index.ts with the correct signature registerPlugin(name: string, settings: PluginSettings): PluginSettings | null.
  • GAP: The doc does not mention that registerPlugin enforces a naming convention (lowercase alphanumeric characters or dashes, starting with a letter) and will log a console error and return null if the name is invalid. Developers would benefit from knowing this constraint upfront.
  • GAP: The doc does not mention unregisterPlugin, getPlugin, or getPlugins — all three are exported from @wordpress/plugins and would be useful to developers managing plugin lifecycle (e.g. conditionally removing plugins or inspecting registered ones).
