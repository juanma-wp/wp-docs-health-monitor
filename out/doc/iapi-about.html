Positives

  • The doc's JS store example correctly uses store('wpmovies', { actions: { toggle: () => { const context = getContext(); context.isOpen = !context.isOpen; } } }) — this matches the actual store() and getContext() signatures exported from packages/interactivity/src/store.ts and packages/interactivity/src/scopes.ts.
  • The doc correctly identifies wp_interactivity_data_wp_context() as the PHP helper for outputting data-wp-context attributes in dynamic block templates, consistent with the Interactivity API's PHP-first design.
  • GAP: The store() function supports a lock option (StoreOptions.lock) that can be true, false, or a string to create private/locked namespaces. The doc never mentions this capability, which is important for plugin authors who want to prevent other code from accessing their store namespace.
