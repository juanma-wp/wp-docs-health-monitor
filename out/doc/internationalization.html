WordPress will check for a file in that path with the format ${domain}-${locale}-${handle}.json as the source of translations. Alternatively, instead of the registered handle you can use the md5 hash of the relative path of the file, ${domain}-${locale} in the form of ${domain}-${locale}-${md5}.json.

$file_base       = 'default' === $domain ? $locale : $domain . '-' . $locale;
	$handle_filename = $file_base . '-' . $handle . '.json';
💡

Update the file-naming description to accurately reflect both lookup patterns used by load_script_textdomain().

  • For the handle-based filename: when $domain is 'default', the format is ${locale}-${handle}.json; otherwise it is ${domain}-${locale}-${handle}.json.
  • For the md5-based filename (line 1264): when $domain is 'default', the format is ${locale}-${md5}.json; otherwise it is ${domain}-${locale}-${md5}.json.
  • Remove the malformed sentence fragment ending in ${domain}-${locale} in the form of ${domain}-${locale}-${md5}.json. — the opening clause is syntactically broken and the format it describes is only correct when domain is not 'default'.
