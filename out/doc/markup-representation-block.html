Positives

  • The doc correctly describes that block settings and attributes are stored as a JSON object inside the block comment — the image save.js confirms sizeSlug is a real attribute of the Image block, consistent with the example <!-- wp:image {"sizeSlug":"large"} -->.
  • The doc accurately states that for dynamically rendered blocks, save is set to null and only a placeholder comment with block attributes is saved — this is a well-established WordPress core behaviour correctly described.
  • GAP: The Image block's save function also persists href, linkTarget, rel, linkClass, width, height, aspectRatio, scale, focalPoint, id, title, and caption attributes, as well as block bindings metadata. Developers building custom Image block variations or deprecations would benefit from knowing the full attribute surface that affects saved markup, not just sizeSlug.
