Positives

  • The useEntityProp hook signature documented as useEntityProp('postType', postType, 'meta') correctly matches the actual implementation signature useEntityProp(kind, name, prop, _id) in packages/core-data/src/hooks/use-entity-prop.js, and the documented return value of [value, setter, fullValue] matches the code's return [value, setValue, fullValue].
  • The register_post_meta PHP example correctly uses show_in_rest: true, single: true, and type: 'string' — all valid parameters confirmed by the register_post_meta($post_type, $meta_key, array $args) signature in src/wp-includes/post.php.
  • GAP: The useEntityProp hook accepts an optional fourth parameter _id (an entity ID to use instead of the context-provided one), which the documentation never mentions. This lets block authors read/write meta for a specific post ID rather than the nearest context-provided entity — useful for blocks that operate on a different post than the one being edited.
