Positives

  • The block_parser_class filter name is correctly documented and matches the actual firing site in parse_blocks() at src/wp-includes/blocks.php (L2427: $parser_class = apply_filters( 'block_parser_class', 'WP_Block_Parser' )).
  • The documented parse method requirement on the custom parser class is accurate — parse_blocks() instantiates the filtered class and calls $parser->parse( $content ) directly.
  • GAP: The block_parser_class filter receives the current parser class name as its first argument (default 'WP_Block_Parser'), but the doc's example callback ignores $prev_parser_class entirely. Developers who want to conditionally replace the parser (e.g., only when not already overridden) would benefit from knowing the argument carries the previously-set class name.
