Positives

  • The doc correctly describes wp_register_block_types_from_metadata_collection() as accepting two parameters ($path and $manifest), matching the PHP function signature function wp_register_block_types_from_metadata_collection( $path, $manifest = '' ) in src/wp-includes/blocks.php.
  • The doc accurately states that registerBlockType() accepts either a block name string or a metadata object as its first parameter, which matches the two overloaded TypeScript signatures in packages/blocks/src/api/registration.ts.
  • GAP: register_block_type() also accepts a complete WP_Block_Type instance as its first parameter (documented in the PHP source: "or a complete WP_Block_Type instance. In case a WP_Block_Type is provided, the $args parameter will be ignored"), but the doc only mentions the string path and directory forms. Developers building programmatic registration flows would benefit from knowing this.
