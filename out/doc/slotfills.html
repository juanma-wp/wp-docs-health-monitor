Positives

  • The registerPlugin usage example correctly uses { render: PluginPostStatusInfoTest } as the settings object, which matches the WPPlugin interface's render: ComponentType requirement in packages/plugins/src/api/index.ts.
  • The conditional-rendering pattern using postTypeObject?.viewable is a sound approach — getCurrentPostType() from editorStore and getPostType() from coreStore are real selectors, and the logic correctly distinguishes Post Editor vs Site Editor contexts.
  • GAP: createSlotFill now returns a name property (the slot key) in addition to Fill and Slot. This is useful for consumers who need to reference the slot key programmatically (e.g. via slotFill.name instead of the deprecated slotFill.Slot.__unstableName), but the doc's definition example omits it entirely.
