Static or Dynamic rendering of a block

100 healthy

✅ No issues found.

Positives

  • The doc correctly describes both dynamic rendering methods (render_callback argument and render.php file via the render property in block.json), which matches the implementation in register_block_type_from_metadata in src/wp-includes/blocks.php where both $args['render_callback'] and the render metadata field are handled.
  • The doc accurately states that when save returns null, the Block Editor skips the block markup validation process — this is consistent with how WordPress handles dynamic blocks that store only the block delimiter comment.
  • GAP: The doc does not mention that when using render.php, the file receives $attributes, $content, and $block as PHP variables (not function parameters) via require $template_path inside a closure — developers writing render.php files need to know these are available as local variables, not function arguments, which is a meaningful distinction from the render_callback approach.
