💡

Update the settings.typography.textIndent type column in the documentation table to accurately reflect the constrained allowed values.

  • Change the type from boolean, string to false | "subsequent" | "all" — the boolean form only accepts false (not true), and the string form only accepts "subsequent" or "all" (not arbitrary strings).
  • A developer who passes true or any arbitrary string (e.g. "first") will fail schema validation, because the doc's current boolean / string labels imply a much wider set of accepted values than the schema actually permits.

Positives

  • The documentation accurately lists settings.spacing.units default as ["px","em","rem","vh","vw","%"], which matches the schema's "default": [ "px", "em", "rem", "vh", "vw", "%" ] exactly.
  • The documentation correctly documents settings.typography.fluid as accepting either boolean or { minFontSize, maxViewportWidth, minViewportWidth }, which matches the schema's oneOf definition precisely.
  • GAP: The settings.typography.textIndent property only accepts false (not any boolean) or one of the strings "subsequent" / "all". The doc's type column says boolean, string without these constraints, which would mislead a developer into thinking true or arbitrary strings are valid values.
