Positives

  • The doc's description of select as pre-bound to state and not waiting for resolvers is accurate — the code confirms select returns CurriedSelectorsOf<T> (state pre-bound) while resolveSelect returns promise-wrapped selectors (CurriedSelectorsResolveOf<T>).
  • The async thunk pattern shown for saveTemperatureToAPI (( temperature ) => async () => { ... }) correctly illustrates the supported thunk signature — the @wordpress/data redux-store implementation supports both plain and async thunk functions.
  • GAP: The doc never mentions that resolveSelect inside a thunk returns a promise (it shows await resolveSelect.getTemperature() without the async keyword on the outer thunk function in that snippet), which could confuse developers about when async is required on the thunk itself.
