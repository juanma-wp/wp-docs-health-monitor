Positives

  • The doc correctly describes getServerState() and getServerContext() as returning deep clones (snapshots) that do not affect the actual state/context when mutated — this matches deepClone(serverStates.get(ns)) in store.ts and deepClone(scope.serverContext[...]) in scopes.ts.
  • The doc accurately states that getConfig() returns static, non-reactive config data — matching the implementation in store.ts where storeConfigs is a plain Map with no signal/proxy wrapping.
  • GAP: store() accepts a lock option (StoreOptions.lock) that can be true, false, or a string to create private/locked namespaces. This is a meaningful capability for plugin authors who want to prevent other code from accessing their store, but the doc never mentions it.
